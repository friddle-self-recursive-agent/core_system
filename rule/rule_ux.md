# Rule — 人机交互（R-UX）

> 所属：[rule.md](rule.md) 规则目录。规则 ID 全局稳定，拆分不改号。落地设计：core_system_instance `acceptance/console/console-ui.md`。

## R-UX-1 人机交互默认对话（2026-11-24 用户裁决）

**所有与人的交互默认是对话（session 对话），不是表单**。表单/结构化直填仅为降级或精修入口。适用于一切录入面（Proposal、Workflow、Role、ServiceDesc、文档编辑、审批说明……）。

固定顺序（缺一不可）：

1. **自由描述 + 自动上下文**：用户可用一段话描述；系统自动获得已知上下文（当前系统/对象/权限/历史对象）并预填。
2. **自动补充**：能推断的直接填（提出人=当前主体、优先级缺省、产物落点缺省、scope 按当前系统）。
3. **缺少询问**：只问 scheme 中**不明确/缺失/冲突**的字段（不做无意义逐项盘问）；每次提问带默认值与示例；用户跳过则用默认。
4. **提交节点 LLM 生成格式**：字段齐 → LLM 依 spec 生成对象 → R-PUB lint + spec 准入 dry-run → 不通过**指出具体字段**并回对话补。
5. **确认后自动补全**：用户看 diff 确认 → Apply（高危 → 审批）；系统补 proposer/status/timestamps 等缺省；敏感项禁止手填（secret 仅引用式）。
6. **降级**：LLM 不可用或用户显式选择 → 回退表单/结构化直填；**两条路产同一对象，无双源**。

红线：对话只是录入辅助——入库前必须经同一准入/权限/事件链；对话原文不落公共库（R-PUB）；不得绕过审批。

## R-UX-2 scheme 驱动编辑控件（2026-11-24 用户裁决）

「scheme 可以进行编辑。该进行 select 的 selector，该填写的填写。」

1. **一切录入/编辑面由 scheme 字段定义驱动**（对话字段卡、降级表单、对象编辑器、设计文档中的 spec 片段）：字段集、类型、必填、枚举、默认值一律取自 scheme（单一真相），UI 不硬编码字段。
2. **控件映射（机读）**：
   - 枚举（`a|b|c` 或闭合集）→ **selector（下拉/分段选择）**，不得让用户手输；
   - 字符串 → input；长文本 → textarea；
   - 数组 → 列表编辑器（逐项增删，行内类型同上）；
   - 引用（`ref`）→ 对象选择器（按 kind/scope 搜索，显示名字与 rv）；
   - bool → switch；map → 键值编辑器；数字 → number input（带范围）。
3. **校验双保险**：控件级即时校验（必填/枚举/长度/正则/引用存在性）+ 提交前 spec 准入 dry-run；错误定位到字段。
4. **scheme 可编辑**：Scheme 本体与各 kind 的 spec 片段是文档——经设计文档编辑面（能力 A/对象编辑）修改，走同一权限/事件/准入链；**禁止绕过 lint/准入的直接改动**。
5. **判据**：抽查字段控件类型=scheme 映射；枚举字段无法手输非法值；必填/引用校验即时生效；改 scheme 后 UI 自动反映（无硬编码残留）。

## R-UX-3 界面用户视角：工程黑话不入界面（2026-11-26 用户裁决）

**概念仍归概念（scheme/文档/代码保持术语），但界面一律按人设计、以用户理解为准。**

1. **「面」字族禁入界面**：内部工程分面词（事件面/指标面/文档面/权限面/场景面/读面/写面/派单面/动作面/判定面/投影面……）不得出现在任何界面文案、屏名、按钮、提示中；界面用自然语言（「事件」「指标」「文档」「权限」「场景」）。工程词形只存在于文档与代码。
2. **内部里程碑/判据词不上界面**：`E4`/`E7`、`L<n>-`、`P-0x`、「真数据」「declared-deferred」等实现进度词形不得作为界面文案（进度词只进验收报告与文档）。
3. **功能与业务按用户心智组织**：用户看到的是「系统 / 服务 / 实例 / 工作流 / 事件 / 审批 / 提案 / 会话」，不是文档对象树或 scheme 分面；kind 名（ServiceDesc/ConnectorOps 等）降为次级徽章，不作主标题。
4. **同一对象双名制**：界面名（人话）为主展示，scheme/术语名为次级注记（tooltip/详情页）；两名在界面上必须可对应（用户点开能看到术语，不脱钩）。

判据：界面文案字符串清单断言零「面」字工程用法、零内部里程碑词形；屏幕主标题=用户视角命名。

## R-UX-4 内容展示渲染优先：markdown 先行、scheme 次级（2026-11-26 用户裁决）

1. **默认视图=渲染后的成品**：文档/内容类（设计文档、desc/goal、报告、事件详情长文）默认展示渲染后的 markdown（标题层级/列表/表格/代码块/链接可交互），用户首先看到的是可读成品，不是源码。
2. **scheme/YAML/原文=次级视图**：结构化细节走「scheme / 原文」切换或折叠区，**绝不默认铺开为裸 YAML 转储**。
3. **scheme 展示同样要好看**：次级 scheme 视图须结构化（字段卡/分组/枚举高亮/语义标签，只读态复用 R-UX-2 控件映射），不做纯文本转储；字段旁给人话释义。
4. **一切以用户理解为第一优先**：任何视图凡涉及术语按 R-UX-3 给人话标签或释义；**看不懂的界面=缺陷**。

判据：文档类页面默认渲染视图（截图）；scheme 为切换/折叠次级且结构化渲染（截图）；首屏裸 YAML 转储=红。渲染器安全红线：内容渲染前必须 HTML 转义（XSS）；渲染器 vendor 单文件入库或最小自写，零网络依赖。

## R-UX-5 视觉风格锚定 DeepSeek（2026-11-26 用户裁决）

一切 console 界面（含录入对话/字段卡/scheme 视图/系统树）视觉风格=**DeepSeek（dsh 原生）**：token（字号/行高/颜色/圆角/间距/密度）与交互语汇取自 dsh 原生体系（§11 整改基线与 `--dsw-*` 词形延续），**不自造第二套视觉体系**；功能与业务命名按 R-UX-3 用户视角执行。

## R-UX-6 默认主界面=关注报告×对话（2026-11-26 用户裁决）

> 用户原话：「可以用 LLM 跑一个完全的报告出来。哪些值得关注哪些不值得关注。然后默认直接报告旁边可以直接开对话 session，这是主要界面」「你作为业务人员视角你关注是什么。一眼看到的是状态。是异常。是重要系统提案。不是数字的堆叠」。

1. **首屏=报告+对话**：console 默认落地=关注报告（主区）+ 常驻对话栏（侧栏）；不再以指标四宫格/CRUD 表格/概念树作首屏主体。旧 Welcome/总览合并为报告页。
2. **三块固定**：状态 / 异常 / 重要提案与审批；一眼看到的是判断与行动，不是数字。
3. **数字退为证据**：数字只出现在条目证据或明细折叠中，且由服务端注入；首屏不设无出处的大字数字宫格（对 console 设计既有「大数字不许是无出处黑盒」的升级）。
4. **不值得关注显式**：报告必须含「已检查、正常」区（clear）；连它一起空时也要说明检查范围——沉默不得代替结论。
5. **每条可追**：值得关注条目至少 1 条可点证据（ref/事件/运行）；无可点证据不得上屏；LLM 不得编造条目。
6. **一键开聊**：任一条目可在同一界面直接开/续对话，会话自动带该条目的对象 tag 与 ctx（R-CTX-8），不跳页、不丢上下文。
7. **报告是派生物**：不新增 DocType、不入 git、无 revision；机制见 [concepts/attention.md](../concepts/attention.md)；生成失败/数据缺失/陈旧必须显式降级，不静默。
8. **不越权**：报告按查看者权限**生成前**裁剪；LLM 无 Apply/批准/执行权，一切动作回既有入口。

判据：首屏截图=报告+对话双栏且无四宫格数字墙；抽查 3 条 attention 证据可点且 ref/hash 一致；clear 区存在（非空或显式「无异常」+范围）；LLM 断开时页面降级不空白且 `generatedBy=rules` 可见。

## R-UX-7 通用对象工作台（tag/tagType/rule/ctx/ops/scheme 同一套）（2026-11-26 用户裁决）

> 用户原话：「其中整个 session 和文档交互界面做一个通用界面【设计 tagtagtyperule。ctx.操作。有 scheme 预览就 scheme 预览】其中交互也是能在交互中用 markdown 画出相应重点」「其中 workflow 也是这样的」。

1. **一个工作台，所有对象**：文档、会话、Workflow、Service/Instance、事件、提案、审批共用同一套「对象工作台」；不为每个概念另造一套 CRUD 页。
2. **固定片（缺片不装假）**：
   - **标签**：tags 按 tagType 分组，可点=同 tag 的对象/文档；
   - **规则**：该 scope/kind/tag 命中的 Rule 文档（可点原文），显式列命中来源；无=「无适用规则」；
   - **上下文**：本会话 ctx pack（tagSig / chunks ref+hash / tokens / 来源 / 命中），可展开、可失效（R-CTX-6）；
   - **操作**：按权限可用的 ConnectorOps / Apply / 提案（含风险档与授权来源）；无权限=不显示（不画灰按钮）；
   - **内容**：正文默认渲染 markdown（R-UX-4）；
   - **scheme**：kind 有 scheme 才有，只读字段卡（R-UX-2 映射），YAML 折叠次级；文档类无 spec 时用结构段卡（必填段完成度）+正文。
3. **对话是工作台的一等片**：侧栏常驻，开/续不跳页；回复默认渲染 markdown，并允许/鼓励用标题、表格、引用、警示块把重点画出来（禁纯文本转储）；对象引用一律可点。
4. **Workflow 同构**：workflow 详情默认=报告（发生了什么/值得关注/下一步）+对话；运行/流程图/事件/流转/数据流/配置退为次级 tab；配置编辑仍走 Apply。
5. **单一真相**：片内数据全部来自 Scheme + ops DB + git + ctx（无前端自建状态）；标识符全可点（既有硬线）。

判据：任取 doc / workflow / event 三类对象，工作台各片齐全或显式「无」；有 scheme 的对象默认字段卡且 YAML 折叠；会话回复 markdown 渲染且对象引用可点；workflow 首屏=报告而非配置表。

## R-UX-8 命令行与桌面同源（2026-11-26 用户裁决）

> 用户原话：「看看写一个命令行[对应桌面功能]然后命令行来提交。来触发系统的event而不是再外面点火了」「接下来任务请用cli提交。一旦有bug修复bug保证event自动能成功走循环」。

1. **一个控制面，两个入口**：桌面（console）与命令行（`corectl`）同源——每个桌面功能有对应命令；CLI 不新造 API/DB，不复制状态。
2. **写面唯一**：CLI 写命令只走 `POST /v1/apply` 与 `POST /v1/events`（及既有 secrets 门控面）；与桌面同一权限/准入/事件链，不得直连 DB/文件/进程。
3. **事件点火**：自循环唯一触发=`LoopRequested` 事件（`corectl loop`）→ dispatch root-agent → wake 桥 → 宿主固定 loop 命令拉起 core-headless 会话；**外部 ignite 脚本只作过渡传输，桥验收后退役**。loop 会话结束前用 `corectl loop` 提交下一轮，**不得自行 `setsid` 点火**。
4. **单飞与固定命令**：已有 loop 会话不重复拉起（宿主 pgrep 单飞 + `already-running`）；宿主只执行部署侧配置命令，事件载荷只进日志、不进命令（零注入面）。
5. **地址发现**：宿主就绪写 `~/.dsh/cored.addr`（0600）；CLI 优先级 `--server` > `CORED_ADDR` > 文件；地址属部署侧，不入公开仓。
6. **显式降级**：cored 不可达、桥缺席、命令未配、单飞命中——都必须有明确输出/状态码，不静默、不伪造成功。

判据：`corectl loop` 后 `/v1/events` 有 `LoopRequested`、`/v1/agents/wakes` 有 root 唤醒、宿主日志出现 `spawned` 或 `already-running`；停掉外部 ignite 后，仅靠该事件仍能拉起/续跑循环。

## R-UX-9 任务中心：进行中的工作一处可见（2026-11-26 用户裁决）

> 用户原话：「不通畅啊。给出页面建议吧。按人的视角。这明显不通畅啊。」

1. **一处看全**：所有进行中的工作（loop 会话、workflow run、Task、待审）进同一「任务中心」，按人话分组：正在做 / 等人 / 卡住 / 完成。
2. **每行说人话**：在做什么 / 卡在哪 / 谁在做 / 多久 / 下一步；点开=完整对话 + 节点 + 证据，不再从侧栏「未分组」里翻。
3. **会话与 workflow 双向链接**：会话头显示 `Task / Workflow / 节点 / 关联 run`；workflow 节点显示当前会话/Task；审批项可跳到对应任务。
4. **深链稳定**：选择即更新 `#/task/<id>` 或 `#/session/<id>`，可复制、刷新恢复。
5. **并发可视可调**：并发车道/上限可见（暂停/恢复/改上限=Apply）；排队原因显式（依赖/写集/资源），不静默等待。
6. **人话优先**：不把 session id、run # 当主标题；主标题=任务名/目标/状态。

判据：从审批或工作流任一入口一次点击到达任务/会话；任务行含进度与阻塞原因；会话头显示关联节点；URL 可复制恢复；并发上限调整生效并留痕。
